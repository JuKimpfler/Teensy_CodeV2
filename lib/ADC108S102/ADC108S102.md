# ADC108S102 – 8-Kanal 12-Bit SPI-ADC

Treiber für den **ADC108S102** (8 Kanäle, 12 Bit, SPI). Im Roboter wird der
Baustein als **Motor-ADC** eingesetzt: pro Motor liefert er einen Kanal für
die Drehzahl-Rückmeldung und einen für die Strommessung.

Dateien: `ADC108S102.h`, `ADC108S102.cpp`

---

## Konfiguration

### Instanziierung

```cpp
ADC108S102 ADC_Motor(&SPI, ADC108S102_Motor_CS);
```

| Parameter | Typ | Bedeutung |
|---|---|---|
| `spi_port` | `SPIClass*` | SPI-Instanz, z.B. `&SPI` oder `&SPI1` |
| `chipSelectPin` | `uint8_t` | CS-Pin (im Projekt `ADC108S102_Motor_CS = 30`, Bus `SPI`; die Linien-ADCs teilen sich den Bus über den Dekoder, siehe [`enum.h`](../include/include.md)) |

### SPI-Parameter (fest im Code, `ADC108S102.cpp`)

| Einstellung | Wert |
|---|---|
| Taktfrequenz | `14 000 000` Hz |
| Bit-Reihenfolge | `MSBFIRST` |
| SPI-Modus | `SPI_MODE3` |

Diese Werte stehen direkt in den `SPISettings(...)` in `read()`. Wer sie
ändern will, muss beide `read()`-Überladungen anpassen.

### Kanal-Kommandos

```cpp
int comandlist[8] = {2048, 4096, 6144, 8192, 10240, 12288, 14336, 16384};
```

Das ist die Tabelle der 16-Bit-Kommandowörter, die beim Lesen als
`transfer16()` herausgeschoben werden. Der Index ist der `channel`-Parameter
(0–7).

> **Hinweis:** Beim ADC108S102 liegt das Adressfeld `ADD2..ADD0` laut
> Datenblatt in den Bits 13–11 (also `channel << 11`, gültige Werte
> `0, 2048, …, 14336`). Die Tabelle hier beginnt bei `2048` und endet bei
> `16384` — sie ist also um einen Kanal verschoben und der letzte Eintrag
> liegt außerhalb des Adressfelds. Wenn die Kanalzuordnung im Betrieb nicht
> passt, ist das die erste Stelle zum Nachschauen.

### Skalierung / Mapping

`read(channel, MOT_ADC, ADC_Mode)` rechnet den Rohwert um:

1. Immer: `map(result, 70, 3970, 0, 3300)` → Ergebnis in **mV**
   (70…3970 = angenommener nutzbarer Rohbereich, 0…3300 mV = Referenz 3,3 V).
2. Danach abhängig von den beiden Flags:

| `MOT_ADC` | `ADC_Mode` | Ergebnis |
|---|---|---|
| `false` | – | Spannung in mV (0…3300) |
| `true` | `false` | **Strom**: `abs(map(mV, 0, 3300, -6000, 6000))` |
| `true` | `true` | **Drehzahl**: `abs(map(mV, 0, 3300, -100, 100))` |

Zum Schluss wird auf `0 … 65535` begrenzt.

Die Konstanten `-6000/6000` bzw. `-100/100` sind die Skalen der
Motortreiber-Rückmeldung und müssen zur verbauten Hardware passen.

## API

| Funktion | Beschreibung |
|---|---|
| `void begin()` | Setzt den CS-Pin auf `OUTPUT` und auf `HIGH`. **Startet den SPI-Bus nicht** – `SPI1.begin()` (bzw. `SPI.begin()`) muss vorher separat aufgerufen werden. |
| `uint16_t read(uint8_t channel, bool MOT_ADC = false, bool ADC_Mode = false)` | Liest einen Kanal inkl. Mapping (siehe oben). Ungültiger Kanal (>7) → `0`. |
| `void read(uint16_t (&values)[8])` | Liest alle 8 Kanäle in einer CS-Sequenz. **Ohne Mapping** – liefert die Rohwerte. |
| `uint16_t giveLastValue(uint8_t channel) const` | Letzter für diesen Kanal gespeicherter Wert, ohne neue SPI-Transaktion. |

## Verwendung im Projekt

In [`systemlib`](../systemlib/systemlib.md) wird pro Motor gelesen:

```cpp
MotorVL_D.Speed_real = ADC_Motor.read(MotorVL_AP1, true, true);  // Drehzahl
MotorVL_D.Current    = ADC_Motor.read(MotorVL_AP2, true, false); // Strom
```

Die Kanalnummern `MotorXX_AP1/AP2` kommen aus `enum.h`.

---

## Beispiel

```cpp
#include <SPI.h>
#include <ADC108S102.h>

ADC108S102 adc(&SPI1, 32);

void setup() {
    SPI1.begin();   // wichtig: nicht Teil von begin()
    adc.begin();
}

void loop() {
    uint16_t mV = adc.read(3);          // Kanal 3 als Spannung [mV]

    uint16_t all[8];
    adc.read(all);                       // alle Kanäle roh
}
```

## Bekannte Baustellen

- Die 12-Bit-Rohwerte werden **nicht** mit `& 0x0FFF` maskiert (siehe TODO-
  Kommentar oben in `ADC108S102.cpp`). Die oberen 4 Bit könnten daher in den
  Messwert einfließen.
- `read(uint16_t (&values)[8])` und `read(uint8_t channel, ...)` liefern
  **unterschiedliche Skalen** (roh vs. gemappt) – nicht mischen.
- `begin()` initialisiert den SPI-Bus nicht, obwohl der Doxygen-Kommentar das
  behauptet.
