# PMW3389 – Optischer Bewegungssensor (SPI)

Treiber für den PixArt **PMW3389** – der Sensor aus optischen Gaming-Mäusen.
Im Roboter dient er als **optische Odometrie**: er misst die tatsächliche
Verschiebung über dem Boden (`dx`/`dy`), unabhängig von Radschlupf.

Dateien: `pmw3389.h`, `pmw3389.cpp`

Fremdbibliothek: Copyright (c) 2019 Sunjun Kim, **LGPL 2.1**. Eingebunden von
Rafael (2023). Die SROM-Firmware (4094 Byte) liegt als `PROGMEM`-Array in der
`.cpp`.

---

## Konfiguration

### Instanziierung

```cpp
PMW3389 sensor(&SPI, 10);   // SPI-Instanz, CS-Pin
```

| Parameter | Bedeutung |
|---|---|
| `spi` | Zeiger auf die `SPIClass`-Instanz |
| `ChipSelectPin` | CS/SS-Pin |

> **Wichtig:** Der Zeiger wird gespeichert, intern verwenden alle Transfers
> aber das globale `SPI`-Objekt (Makros `SPI_BEGIN`/`SPI_END` und
> `SPI.transfer(...)`). Der Sensor muss also an **`SPI`** hängen; ein
> `&SPI1` im Konstruktor ändert daran nichts.

`SPI.begin()` muss vor `begin()` aufgerufen werden – der Treiber macht das
nicht (`spi->begin()` ist auskommentiert).

### SPI-Parameter (Makros in `pmw3389.cpp`)

| Einstellung | Wert |
|---|---|
| Taktfrequenz | `8 000 000` Hz |
| Bit-Reihenfolge | `MSBFIRST` |
| SPI-Modus | `SPI_MODE3` |

### Auflösung (CPI)

```cpp
sensor.setCPI(1600);
```

| Eigenschaft | Wert |
|---|---|
| Schrittweite | 50 CPI |
| Registerwert | `constrain((cpi / 50) - 1, 0, 0x013F)` |
| Bereich | 50 … 16 000 CPI |
| **Default in `begin()`** | `254` → gerundet auf 250 CPI |

Der Default von 254 ist ungewöhnlich niedrig. Für Odometrie ist ein höherer
Wert (z.B. 1600) meist sinnvoller: `count / CPI = Zoll`. Nach `begin()` mit
`setCPI()` überschreiben.

### Timing beim Init (`begin()`)

Die Sequenz ist zeitkritisch und darf nicht gekürzt werden:

1. CS-Toggle (Reset der seriellen Schnittstelle)
2. `REG_Shutdown = 0xB6`, dann **300 ms** warten
3. `REG_Power_Up_Reset = 0x5A`, dann **50 ms** warten
4. Register `0x02`…`0x06` lesen und verwerfen
5. SROM-Firmware hochladen (4094 Byte, je 15 µs Pause)
6. `setCPI(254)`

## API

| Funktion | Beschreibung |
|---|---|
| `void begin()` | Reset + Firmware-Upload, siehe oben |
| `void setCPI(uint16_t cpi)` | Auflösung setzen |
| `uint8_t getProductID()` | Register `0x00`; beim PMW3389 = `0x47` |
| `PMW3389_DATA readBurst()` | Ein vollständiger Datensatz (siehe unten) |
| `uint8_t readReg(byte reg)` | Einzelregister lesen |
| `void writeReg(byte reg, byte data)` | Einzelregister schreiben |
| `void prepareImage()` / `readImagePixel()` / `endImage()` | Rohbild auslesen (Debug: 36×36 Pixel) |

### `PMW3389_DATA`

| Feld | Typ | Bedeutung |
|---|---|---|
| `isMotion` | `bool` | Bewegung erkannt |
| `isOnSurface` | `bool` | Sensor auf einer Oberfläche |
| `dx`, `dy` | `int16_t` | Verschiebung in Counts (`CPI × Count = Zoll`) |
| `SQUAL` | `byte` | Oberflächenqualität, max `0x80`; Anzahl Merkmale ≈ `SQUAL × 8` |
| `rawDataSum` | `byte` | Mittelwert ≈ `rawDataSum × 1024 / 1296` |
| `maxRawData`, `minRawData` | `byte` | max/min Rohwert im Frame, max 127 |
| `shutter` | `unsigned int` | Belichtungszeit in Takten des internen Oszillators |

**Interpretation:** `SQUAL` und `shutter` sind die wichtigsten Diagnosewerte.
Niedriges `SQUAL` bei hohem `shutter` = zu wenig Oberflächenstruktur oder
falscher Abstand zum Boden (Linsenbrennweite beachten). Bei
`isOnSurface == false` sind `dx`/`dy` nicht verwertbar.

Burst-Modus: `readBurst()` schaltet automatisch in den Burst-Modus und
verlässt ihn, wenn ein Einzelregisterzugriff erfolgt oder länger als 500 ms
kein Burst gelesen wurde.

## Beispiel

```cpp
#include <SPI.h>
#include "pmw3389.h"

PMW3389 sensor(&SPI, 10);

void setup() {
    SPI.begin();
    sensor.begin();
    sensor.setCPI(1600);

    if (sensor.getProductID() != 0x47) { /* nicht erkannt */ }
}

void loop() {
    PMW3389_DATA d = sensor.readBurst();

    if (d.isOnSurface && d.isMotion) {
        posX += d.dx;
        posY += d.dy;
    }
}
```

Verwendung im Projekt: `test/Positioning.cpp`.

## Bekannte Baustellen

- Der Konstruktor nimmt eine `SPIClass*` entgegen, benutzt wird intern aber
  ausschließlich das globale `SPI` (siehe oben).
- `begin()` ruft `spi->begin()` nicht auf.
- Der Sensor wird von [`systemlib`](../systemlib/systemlib.md) nicht
  eingebunden – die Positionsbestimmung läuft nur im Testprogramm.
- Der Header ist `pmw3389.h` (klein), die Klasse `PMW3389` (groß). Bei
  case-sensitiven Dateisystemen auf die Schreibweise im `#include` achten.
