# XM125 – 60-GHz-Radar (Acconeer A121, I²C)

Treiber für das **Acconeer XM125**-Modul. Zwei Applikationen, je nach
geflashter Firmware: **Distance Detector** (Entfernungen zu bis zu 10 Objekten)
und **Presence Detector** (Anwesenheit über schnelle/langsame Bewegung).

Dateien: `XM125.h/.cpp` (Basis, I²C-Protokoll) · `XM125Distance.h/.cpp` ·
`XM125Presence.h/.cpp`

> **Die ausführliche Dokumentation liegt in [doc/](doc/README.md)** — 12 Kapitel
> von Protokoll und Konfiguration über Kalibrierung bis Troubleshooting.

---

## Kurzeinstieg

```cpp
#include <Wire.h>
#include "XM125Distance.h"

XM125Distance radar(0x51);          // Adresse; WAKE_UP/INT unverkabelt

void setup() {
  Wire.begin();
  Wire.setClock(100000);            // mehr Toleranz für Clock-Stretching
  radar.begin(Wire);

  radar.config.startMm        = 200;
  radar.config.endMm          = 2700;
  radar.config.peakSorting    = XM125D_SORT_CLOSEST;
  radar.config.reflectorShape = XM125D_REFLECTOR_PLANAR;
  radar.applyConfigAndCalibrate();  // dauert bis ~2 s, Umgebung frei halten

  radar.setMeasureTimeout(3000);    // PROFILE5/CFAR braucht länger als der Default
  radar.startMeasurement();         // erste Messung anstoßen
}

void loop() {
  if (radar.isMeasuring()) return;  // läuft noch — die Library wartet nie

  const XM125DistanceResult& res = radar.getLastResult();
  if (res.valid) {
    for (uint8_t i = 0; i < res.numDistances; i++) {
      Serial.println(res.peakDistanceRaw[i]);        // ⚠ noch keine mm!
    }
  }

  radar.startMeasurement();         // nächste Runde
}
```

`Wire.begin()` muss **vor** `begin()` erfolgen — die Library ruft es nicht auf.

## Der Messbetrieb wartet nie

Drei Kommandos, mehr braucht es nicht — und keines davon blockiert:

| Kommando | Bedeutung | Kosten |
|---|---|---|
| `startMeasurement()` | Messung starten | 1 Registerschreibzugriff (< 1 ms) |
| `isMeasuring()` | Läuft eine Messung? (treibt dabei die Zustandsmaschine) | höchstens 1 Registerlesezugriff |
| `getLastResult()` | Letztes Messergebnis (`XM125DistanceResult`) | 0 — reiner Cache-Zugriff |

Mehrere Sensoren messen dadurch **gleichzeitig**: bei allen
`startMeasurement()` aufrufen, danach reihum `isMeasuring()`. Die Messdauer
(20–200 ms) fällt einmal für alle an statt einmal pro Sensor, und der Zyklus
steht dafür nie still. Details: [02-Distance-Detector.md](doc/02-Distance-Detector.md).

`measureBlocking()` gibt es weiterhin — aber ausschließlich für Kalibrier- und
Testskripte, die ohnehin nichts anderes tun.

## Zwei Dinge, die man vorher wissen sollte

1. **Kalibrierung ist Pflicht und flüchtig.** Nach jedem Power-On einmal
   `applyConfigAndCalibrate()` — währenddessen darf sich vor dem Sensor nichts
   bewegen, weil die Umgebung als Referenz aufgenommen wird. Steckt ein Modul
   fest (`DETECTOR_ERROR`, dauerhaft `BUSY`, dauerhaft Unsinn), gibt es
   `hardCalibration()`: Modul-Reset, danach **alle** Konfigurationsregister neu
   und kalibrieren — alles in einem Aufruf.

   ```cpp
   radar.hardCalibration();                     // Neustart + Werksvorgabe
   radar.hardCalibration(150, 2500);            // einzelne Werte per Parameter

   XM125DistanceConfig cfg;                     // oder benannt (empfohlen)
   cfg.startMm        = 150;
   cfg.reflectorShape = XM125D_REFLECTOR_PLANAR;
   radar.hardCalibration(cfg);
   ```

   Das blockiert ~1–3 s und gehört ins Hochfahren, nicht in den Zyklus.
   Details: [07, Teil A](doc/07-Kalibrierung.md#teil-a--modul-interne-kalibrierung).
2. **`getPeakDistanceMm()` liefert noch keine Millimeter.** Die Firmware auf
   diesen Modulen kodiert die Peak-Distanz abweichend; der Umrechnungsfaktor
   ist offen. Für Messreihen `getPeakDistanceReg()` (volles Registerwort)
   protokollieren, Werkzeug: `lib/XM125/examples/XM125_WallCalibration.cpp`. Details:
   [07, Teil B](doc/07-Kalibrierung.md#teil-b--kalibrierung-der-peak-rohwerte-counts--mm).

## Beispiele

Alle Beispiel-/Testskripte liegen unter
[lib/XM125/examples/](examples/README.md) (ausführliche Erklärung jedes
Skripts dort). Bauen: gewünschte Datei nach `src/main.cpp` des Hauptprojekts
kopieren (in `src/` darf immer nur eine Datei mit `setup()`/`loop()` liegen)
und normal bauen/hochladen:

```bash
cp lib/XM125/examples/XM125_Connectivity.cpp src/main.cpp
pio run -e teensy40 -t upload
```

Weitere: `XM125_Distance`, `XM125_Distance_Multi`, `XM125_Presence`.

Kalibrierung — ein Skript je Methode, in dieser Reihenfolge fahren
([Übersicht](doc/07-Kalibrierung.md#ein-skript-je-kalibriermethode)):

| Skript | Methode |
|---|---|
| `XM125_Calib_Module` | Modul-interne Kalibrierung: läuft sie durch, wie lange, hält sie warm? |
| `XM125_Calib_Alignment` | Sensor mechanisch auf maximale Echostärke ausrichten |
| `XM125_Calib_Sensitivity` | `signalQuality` × `thresholdSensitivity` (+ Profil, Reflektorform) |
| `XM125_Calib_Crosstalk` | Übersprechen: stören sich die gleichzeitig messenden Sensoren? |

`XM125_WallCalibration` bleibt für die offene Rohwert↔mm-Messreihe (Teil B).
