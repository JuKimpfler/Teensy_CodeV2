# INA219 – Strom-, Spannungs- und Leistungsmessung (I²C)

Treiber für den TI **INA219** High-Side Current/Power Monitor. Im Roboter
werden zwei Instanzen für die Überwachung von Haupt- und Motorstromkreis
genutzt.

Dateien: `INA219.h`, `INA219.cpp`

**Fremdbibliothek:** Rob Tillaart, Version 0.3.1,
<https://github.com/RobTillaart/INA219> (MIT). Änderungen hier bitte
dokumentieren, sonst gehen sie beim nächsten Update verloren.

---

## Konfiguration

### Instanziierung und Start

```cpp
INA219 INA219_Main(0x40);
INA219 INA219_Motor(0x41);

INA219_Main.begin(Wire1);
INA219_Main.setMaxCurrentShunt(15);   // Pflicht!
```

| Schritt | Bedeutung |
|---|---|
| Konstruktor | I²C-Adresse, gültig `0x40`…`0x4F` (per A0/A1-Pins einstellbar) |
| `begin(TwoWire&)` | Bus zuweisen; gibt `false` zurück, wenn der Baustein nicht antwortet |
| `setMaxCurrentShunt(...)` | **Kalibrierung – ohne sie liefert `getCurrent()`/`getPower()` 0** |

`Wire.begin()` muss vorher erfolgt sein.

### Kalibrierung

```cpp
bool setMaxCurrentShunt(float maxCurrent = 3.4, float shunt = 0.002);
```

| Parameter | Bedingung | Bedeutung |
|---|---|---|
| `maxCurrent` | ≥ 0,001 | erwarteter Maximalstrom in A – bestimmt die Auflösung: `current_LSB = maxCurrent / 32768` |
| `shunt` | ≥ 0,001 | Shunt-Widerstand in Ω |

Im Projekt: `setMaxCurrentShunt(15)` → 15 A Vollausschlag, Shunt beim Default
**0,002 Ω**. Wenn auf der Platine ein anderer Shunt sitzt, ist der zweite
Parameter zwingend anzugeben, sonst stimmen alle Stromwerte proportional
nicht.

`#define PRINTDEBUG` (in `INA219.cpp` auskommentiert) gibt die berechneten
Kalibrierwerte über `Serial` aus.

### Messbereich und Verstärkung

| Funktion | Werte | Bedeutung |
|---|---|---|
| `setBusVoltageRange(uint8_t v)` | `16` oder `32` | Bus-Messbereich in V (Zwischenwerte werden gerundet) |
| `setGain(uint8_t factor)` | `1, 2, 4, 8` | PGA am Shunt: ±40 / ±80 / ±160 / ±320 mV |

### ADC-Einstellungen (je für Bus und Shunt)

Jeweils **eine** der drei Varianten verwenden:

| Funktion | Bereich | Wirkung |
|---|---|---|
| `setBusResolution(bits)` / `setShuntResolution(bits)` | 9…12 | Auflösung, immer 1 Sample |
| `setBusSamples(value)` / `setShuntSamples(value)` | 0…7 | Mittelung über 2^value Samples, immer 12 Bit |
| `setBusADC(mask)` / `setShuntADC(mask)` | 0x00…0x0F | Rohmaske laut Datenblatt |

Mehr Samples = weniger Rauschen, aber längere Wandlungszeit.

### Betriebsmodi

`setMode(0…7)` bzw. die benannten Wrapper:

| Mode | Wrapper | Bedeutung |
|---|---|---|
| 0 | `shutDown()` | Power-Down |
| 1 | `setModeShuntTrigger()` | Shunt, getriggert |
| 2 | `setModeBusTrigger()` | Bus, getriggert |
| 3 | `setModeShuntBusTrigger()` | beides, getriggert |
| 4 | `setModeADCOff()` | ADC aus |
| 5 | `setModeShuntContinuous()` | Shunt, kontinuierlich |
| 6 | `setModeBusContinuous()` | Bus, kontinuierlich |
| 7 | `setModeShuntBusContinuous()` | **Default**, beides kontinuierlich |

## Messwerte

| Funktion | Einheit | Hinweis |
|---|---|---|
| `getShuntVoltage()` | V | LSB fest 10 µV |
| `getBusVoltage()` | V | LSB fest 4 mV; liefert **−100** bei Math-Overflow |
| `getCurrent()` | A | nur nach Kalibrierung gültig |
| `getPower()` | W | nur nach Kalibrierung gültig |

Zusätzlich gibt es zu jedem Wert `_mV` / `_mA` / `_mW` und `_uV` / `_uA` /
`_uW` als Skalierungshelfer.

Statusflags: `getMathOverflowFlag()`, `getConversionFlag()`.
Diagnose: `isCalibrated()`, `getCurrentLSB()`, `getShunt()`, `getMaxCurrent()`,
`getRegister(reg)`.

## Verwendung im Projekt

[`systemlib`](../systemlib/systemlib.md) verwendet zwei Instanzen an `Wire1`:

| Instanz | Adresse | Zugriff über systemlib |
|---|---|---|
| `INA219_Main` | `0x40` | `giveMainVoltage()`, `giveMainCurrent()` |
| `INA219_Motor` | `0x41` | `giveMotorVoltage()`, `giveMotorCurrent()` |

`giveMotorCurrent()` glättet zusätzlich über einen gleitenden Mittelwert von
6 Messungen, weil der Motorstrom stark pulsiert.

PDS-Kanäle 1–4 tragen Spannungen und Ströme: 1 = Akku_V, 2 = Akku_I,
3 = Motor_V, 4 = Motor_I (siehe [`docs/PDS_Belegung.md`](../../docs/PDS_Belegung.md)). `systemlib::readSensors()` fragt die
beiden INA219 dafür mit 10 Hz ab – im 100-Hz-Takt würden die vier
I2C-Zugriffe die Zykluszeit spürbar verlängern.

## Beispiel

```cpp
#include <Wire.h>
#include <INA219.h>

INA219 ina(0x40);

void setup() {
    Wire.begin();
    if (!ina.begin(Wire)) { /* nicht gefunden */ }

    ina.setMaxCurrentShunt(15.0, 0.002);
    ina.setBusVoltageRange(32);
    ina.setGain(8);
}

void loop() {
    float v = ina.getBusVoltage();
    float i = ina.getCurrent_mA();
}
```

## Bekannte Baustellen

- `getPower()` verwendet den Faktor `_current_LSB * 20`; im Datenblatt ist der
  Power-LSB `20 × current_LSB` – passt, gilt aber nur bei korrekter
  Kalibrierung.
- `_readRegister()` prüft nicht, ob wirklich 2 Byte gelesen wurden.
- Der Aufruf im Projekt nutzt den Shunt-Default `0.002 Ω` – gegen die reale
  Platine gegenprüfen.
