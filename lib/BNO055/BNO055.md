# BNO055 – 9-DOF Absolut-Orientierungssensor (I²C)

Schlanker Treiber für den Bosch **BNO055**. Genutzt wird im Roboter vor allem
der Heading-Winkel (`eulHeading()`) für die Ausrichtungsregelung.

Dateien: `BNO055.h`, `BNO055.cpp`

---

## Konfiguration

### Instanziierung

```cpp
BNO055 BNO(BNO_ADDRESS, &I2C_BNO);
```

`BNO_ADDRESS` (`0x28`) und `I2C_BNO` (`Wire`) kommen aus
[`params.h`](../include/include.md).

| Parameter | Bedeutung |
|---|---|
| `addr` | I²C-Adresse, `0x28` (ADR-Pin low) oder `0x29` |
| `i2c_class` | Zeiger auf die `TwoWire`-Instanz (`&Wire`, `&Wire1`, …) |

`Wire.begin()` + `Wire.setClock(...)` müssen **vor** `begin()` erfolgen.

### Compile-Zeit-Schalter (`BNO055.h`)

| Define | Default | Wirkung |
|---|---|---|
| `DEFAULT_OPR_MODE` | `OPR_MODE_IMU` | Betriebsmodus, in den `begin()` den Sensor schaltet |
| `CALIBRATION_ENABLED` | **auskommentiert** | Schaltet Speichern/Laden der Kalibrierdaten im EEPROM ein |
| `EEPROM_BNO_CALIB` | `250` | Startadresse der Kalibrierdaten im EEPROM |
| `EEPROM_BNO_CALIB_SIZE` | `22` | Länge des Kalibrierblocks in Byte |
| `BNO055_SENSOR_FUSION_ALGO` | `5` | derzeit nur Doku-Wert, wird im Code nicht verwendet |

### Betriebsmodi

Non-Fusion (Rohdaten):
`OPR_MODE_ACCONLY`, `MAGONLY`, `GYROONLY`, `ACCMAG`, `ACCGYRO`, `MAGGYRO`, `AMG`

Fusion (berechnete Orientierung):

| Modus | Sensoren | Eigenschaft |
|---|---|---|
| `OPR_MODE_IMU` | Acc + Gyro | **Default.** Relativer Heading, kein Magnetometer → unempfindlich gegen Störfelder, driftet aber langsam |
| `OPR_MODE_COMPASS` | Acc + Mag | Absoluter Kompass |
| `OPR_MODE_M4G` | Acc + Mag | Gyro-freie Rotationserkennung |
| `OPR_MODE_NDOF_FMC_OFF` | alle | 9-DOF ohne Fast-Magnet-Calibration |
| `OPR_MODE_NDOF` | alle | volle 9-DOF-Fusion, absoluter Heading |

Für den Roboter ist `IMU` bewusst gewählt: auf dem Spielfeld sind
Motoren/Metall zu störend für das Magnetometer. Der Heading ist damit
**relativ** – die Nullrichtung wird per `systemlib::calibBNO()` softwareseitig
gesetzt.

### Einheiten (`REG_UNIT_SEL`, in `begin()` gesetzt)

```cpp
buffer[1] = (1 << 7) | (0 << 4) | (0 << 2) | (0 << 1) | (1 << 0);
```

| Bit | Wert | Bedeutung |
|---|---|---|
| 7 | 1 | Ausgabeformat **Android** (beeinflusst Vorzeichen der Pitch-Werte) |
| 4 | 0 | Temperatur in °C |
| 2 | 0 | Euler-Winkel in Grad |
| 1 | 0 | Drehrate in °/s |
| 0 | 1 | Beschleunigung in **mg** (0 wäre m/s²) |

> Achtung: Bit 0 ist auf `1` gesetzt, der Kommentar im Code beschreibt aber
> m/s². Wer `accData*()` in m/s² braucht, muss dieses Bit auf 0 setzen.

## API

### Setup / Status

| Funktion | Beschreibung |
|---|---|
| `void begin()` | Config-Modus → (optional Kalibrierdaten aus EEPROM) → Einheiten setzen → `DEFAULT_OPR_MODE` |
| `void reset()` | Löst System-Reset aus (`SYS_TRIGGER` Bit 5); mit `CALIBRATION_ENABLED` wird zusätzlich der EEPROM-Block genullt |
| `uint8_t calibStatus()` | Register `CALIB_STAT`: je 2 Bit für Sys / Gyro / Acc / Mag, `3` = voll kalibriert |
| `e_bnoSysStatus systemStatus()` | Systemzustand als Enum (siehe unten) |
| `uint8_t systemError()` | Register `SYS_ERR` |
| `void updateCalibrationData()` | **nur mit `CALIBRATION_ENABLED`**: liest die 22 Kalibrierbytes und schreibt sie ins EEPROM |

`e_bnoSysStatus`: `systemIdle`, `systemError`, `initializingPeripherals`,
`systemInitialization`, `executingSelftest`, `sensorFusionAlgorithmRunning`,
`systemRunningWithoutFusionAlgorithm`

### Messwerte

| Funktion | Einheit | Register |
|---|---|---|
| `eulHeading()` | Grad (0…360) | `0x1A` |
| `eulRoll()` | Grad | `0x1C` |
| `eulPitch()` | Grad | `0x1E` |
| `quaData(float* data)` | Quaternion `[w,x,y,z]`, normiert (`/2^14`) | ab `0x20` |
| `quaDataW/X/Y/Z()` | einzelne Quaternion-Komponente | `0x20`…`0x26` |
| `accDataX/Y/Z()` | siehe Einheiten-Bit oben | `0x08`…`0x0C` |
| `magDataX/Y/Z()` | µT (Rohwert /16) | `0x0E`…`0x12` |
| `gyrDataX/Y/Z()` | °/s | `0x14`…`0x18` |

Die `request*()`-Funktionen (`requestQuaData`, `requestGyrDataZ`,
`requestSystemStatus`) setzen nur die Leseadresse und stoßen ein
`requestFrom()` an, ohne die Daten abzuholen — gedacht für nicht-blockierendes
Lesen, aktuell im Projekt nicht verwendet.

## Verwendung im Projekt

[`systemlib`](../systemlib/systemlib.md) legt die globale Instanz `BNO` an und
liest zyklisch:

```cpp
BNO_eulerZ   = Util.wrapAngle(BNO.eulHeading());              // → ±180°
BNO_OrbitDir = Util.wrapAngle(BNO_eulerZ - BNO_calibration);  // relativ zur Nullrichtung
```

`calibBNO()` friert die aktuelle Richtung als Nullpunkt ein
(`BNO_calibration = BNO_eulerZ`). Der Heading-Regler arbeitet dann auf
`BNO_OrbitDir`.

PDS-Kanäle (gebunden in `systemlib::setupPDS()`, siehe [`docs/PDS_Belegung.md`](../../docs/PDS_Belegung.md)):
5 = Heading (`BNO_eulerZ`), 6 = Orbit_Dir, 7 = BNO_Nullpunkt
(`BNO_calibration`). Der Kalibrier-/System-Status des BNO ist noch auf keinem
Kanal – dafür sind 26–31 frei.

---

## Beispiel

```cpp
#include <Wire.h>
#include <BNO055.h>

BNO055 bno(0x28, &Wire);

void setup() {
    Wire.begin();
    Wire.setClock(400000);
    bno.begin();
}

void loop() {
    float heading = bno.eulHeading();   // 0..360 Grad
    uint8_t cal   = bno.calibStatus();  // Bits: SYS|GYR|ACC|MAG
}
```

## Bekannte Baustellen

- Die Registerliste in `BNO055.h` ist unvollständig (TODO im Code); viele
  Zugriffe nutzen hartcodierte Adressen.
- `gyrDataX/Y/Z()` teilen intern durch `10.0f`, geben aber `int16_t` zurück –
  die Nachkommastelle geht verloren.
- `getWords()` prüft `cls->available() != 8` fest auf 8 Byte, funktioniert
  also nur für `numWords == 4` (Quaternionen) zuverlässig.
- Kalibrierung ist per Default **aus** (`CALIBRATION_ENABLED` auskommentiert);
  der Sensor startet damit nach jedem Reset unkalibriert.
